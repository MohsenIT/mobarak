# راهبری پل بله و GitHub

## دسترسی‌ها

توکن‌ها در Cloudflare Secrets قرار می‌گیرند؛ هیچ توکنی در Git، خروجی آزمون یا متن کانال قرار نمی‌گیرد. فایل‌های `.secrets` محلی فقط برای راه‌اندازی هستند و در بسته سورس قرار نمی‌گیرند. توکن Cloudflare فقط Workers Scripts/D1 و توکن GitHub فقط مخزن تعیین‌شده با Issues/Webhooks را پوشش می‌دهند.

## رفتار کاربر

- پیام خصوصی متنی تا ۲۸۰۰ نویسه → پیش‌نمایش کامل، دسته پیشنهادی و موضوع‌های مشابه.
- دکمه تأیید → انتشار عمومی همان متن در Issue و یک پست کانال. نام و شناسه خصوصی منتشر نمی‌شود.
- دکمه موضوع مشابه → لینک Issue و پست قبلی؛ Issue تکراری ساخته نمی‌شود.
- `/comment 42 متن` → پیش‌نمایش و تأیید توضیح تکمیلی.
- `/status 42` → وضعیت GitHub؛ `/report 42 دلیل` → گزارش خصوصی محتوای نامناسب به مدیر.
- `/cancel` → لغو پیش‌نویس تأییدنشده؛ `/forget` → حذف پیش‌نویس و ارتباط پیگیری خصوصی.
- دیدگاه‌های عمومی کانال به GitHub منتقل می‌شوند. هویت نویسنده بله با شناسه نمایشی پایدار و غیرقابل‌برگشت از شناسه خصوصی نشان داده می‌شود؛ نظر GitHub با نام کاربری عمومی همان نویسنده نمایش داده می‌شود.

متن خصوصی تا قبل از تأیید عمومی نمی‌شود. پیش‌نویس ۲۴ ساعت برای تأیید معتبر است. پیش‌نویس منقضی و محتوای صف قدیمی پس از حداکثر هفت روز از مهلت مربوط پاک می‌شوند. رویدادهای موفق بلافاصله از متن خام خالی می‌شوند. تاریخچه محتوای عمومی، نگاشت‌ها و عملیات لازم برای جلوگیری از تکرار نگه‌داری می‌شوند. حالت‌های خطای قدیمی با متن پاک‌شده باید با اطلاعات تازه منبع بازبینی شوند، نه بازپخش کور.

## نگاشت پست و دیدگاه

بات باید پیش از انتشار پست در کانال، در گروه دیدگاه عضو و دارای دسترسی پیام‌ها باشد. در آزمون واقعی، رابط وب اجازه افزودن عضو داد؛ مدیریت جداگانه لازم نشد. رویداد خودکار نسخه گروهی پست از Bot API دریافت می‌شود، ولی فیلدهای forward موجود نیستند. نگاشت فقط با این شروط انجام می‌شود:

1. شناسه گروه دقیقاً گروه تنظیم‌شده است.
2. فرستنده از نوع bot و username دقیقاً کانال تنظیم‌شده است؛ کاربر عادی یا بات دیگر پذیرفته نمی‌شود.
3. هش متن عمومی دقیقاً با یکی از نسخه‌های ذخیره‌شده پست تطابق دارد و به یک Issue یکتا می‌رسد؛ زمان و ترتیب مبنای انتساب نیستند.
4. شناسه واقعی ریشه گروه ذخیره می‌شود؛ نظرات بعدی با `message_thread_id` همان ترد به Issue می‌رسند.

پست هر Issue لینک یکتای GitHub را در متن دارد. متن قدیمیِ پست پس از ویرایش برای نگاشت رویدادهای با تأخیر با هش نگه‌داری می‌شود. نظر ترد ناشناخته در صف برای دریافت ریشه صبر می‌کند و حدس زده نمی‌شود. ارسال پاسخ با `reply_to_message_id` ریشه گروه انجام می‌شود؛ ارسال reply به خود کانال پست مستقل می‌سازد و استفاده نمی‌شود.

## خطا و جلوگیری از تکرار

رویداد قبل از پاسخ ۲۰۰ در D1 ثبت می‌شود. شناسه update بله و delivery گیت‌هاب یکتا هستند. صف با lease و cron هر دقیقه پردازش می‌شود. هر اثر خارجی یک کلید پایدار دارد؛ ساخت پست برای هر Issue فقط یک کلید دارد. خطای نرخ/رد موقت با backoff و تلاش محدود تکرار می‌شود. ویرایش‌های هم‌توان قابلیت تکرار دارند.

Bot API برای ارسال پیام کلید idempotency ندارد. اگر پس از ارسال، اتصال قطع شود یا پاسخ گم شود، تکرار خودکار ممکن است پست تکراری بسازد. بنابراین عملیات نوشتنی مبهم `uncertain` می‌شود و خودکار تکرار نمی‌شود. این محدودیت به معنی تضمین تراکنش توزیع‌شده بین دو سرویس نیست. همین محافظ برای POST مبهم GitHub هم اعمال می‌شود.

## مسیرهای مدیر

همه مسیرها به هدر `Authorization: Bearer ADMIN_SECRET` نیاز دارند؛ راز را در URL نگذارید.

- `GET /admin/status`: وضعیت صف، عملیات مبهم و گزارش‌های محتوای نامناسب.
- `GET /admin/events`: شواهد مسیریابی پالایش‌شده ۱۰۰ آپدیت آخر بله.
- `POST /admin/sync` با `{"number":42}`: دریافت وضعیت فعلی Issue و اصلاح پست موجود.
- `POST /admin/retry` با `{"id":"EVENT_ID"}`: تلاش مجدد یک رویداد ناموفق؛ رویداد مبهم پذیرفته نمی‌شود.
- `POST /admin/reconcile` با effectId، eventId و result: فقط پس از مشاهده و تأیید نتیجه واقعی در سرویس خارجی. نتیجه برای ارسال بله شیء شامل message_id واقعی است؛ برای ساخت Issue، شیء کامل Issue که از GitHub GET دریافت شده است. این مسیر نتیجه عملیات مبهم را ثبت و رویداد را دوباره صف‌بندی می‌کند. هیچ مقدار حدسی وارد نکنید.

برای خطای توکن، ابتدا Secret را اصلاح کنید، سپس رویداد failed را retry کنید. رخدادهای uncertain فقط پس از تطبیق با پیام/Issue واقعی بازگردند. برای نتیجه نامعلومِ ارسال بله، اگر پیام یافت نشد هم صرف نیافتن در رابط مدرک عدم ارسال نیست؛ با قطعیت از تکثیر پست جلوگیری کنید.

## کنترل هزینه و محدودیت‌ها

هیچ کد خرید، ثبت دامنه، فعال‌سازی طرح پولی یا سرویس AI پولی وجود ندارد. تشخیص مشابهت با جستجوی GitHub و مقایسه واژگانی نرمال‌شده فارسی/عربی انجام می‌شود؛ تصمیم نهایی با کاربر است. در قطعی جستجو، کش محلی و ثبت گزارش همچنان قابل استفاده‌اند. گزارش خصوصی هر کاربر به ۲۰ پیش‌نویس در روز محدود است. ورودی وب‌هوک سقف حجم دارد و مسیرهای مدیریتی عمومی نیستند.

در صورت اتمام سهمیه Free، پردازش تا بازیابی سهمیه متوقف/با خطا مواجه می‌شود؛ ارتقای خودکار انجام نمی‌شود. پایش سهمیه در داشبورد Cloudflare لازم است. خطاهای D1 یا API باعث انتشار بدون تأیید نمی‌شوند.

## پشتیبان‌گیری و بازگشت

از D1 با فرمان export رسمی Cloudflare پشتیبان بگیرید. برای بازگشت نسخه Worker از rollback رسمی استفاده کنید؛ migrationهای حاضر افزایشی‌اند. برای توقف دریافت بله می‌توان وب‌هوک را با مسیر رسمی حذف کرد؛ نشانی وب‌هوک حاوی راز است و نباید در تیکت/گیت چاپ شود. تغییر صرف BRIDGE_ENABLED به false صف را متوقف می‌کند، اما دریافت پایدار رویداد ادامه دارد.
