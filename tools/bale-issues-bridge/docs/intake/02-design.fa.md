# طراحی اجرایی گفتگو و حاکمیت

## سفر کاربر و ماشین حالت

پیام آزاد → استخراج قواعد/AI → یکی از راهنمایی، سؤال ضروری یا پیش‌نمایش → تأیید → انتشار GitHub → همان پست کانال → پیگیری. هیچ انتخاب نوع یا اولویت اجباری نیست.

حالت‌های پایدار: collecting، clarifying، help، preview، editing_title، editing_body، editing_other، publishing، published، cancelled، resolved. هر گفتگو شناسه غیرشخصی، مالک، revision، تاریخ انقضا، حداکثر متن و شمار سؤال/فراخوانی دارد. callback دارای شناسه و revision است؛ مالک و حالت پیش از هر عمل بررسی می‌شوند. ارسال معمول بعد از preview ادامه توضیح است؛ /new شروع صریح گزارش جدید است. تصویرهای متوالی جمع می‌شوند و دکمه پایان توضیح، آماده‌سازی را انجام می‌دهد. متن کامل مستقیم به preview می‌رود و منتظر تایمر نمی‌ماند.

سؤال‌ها براساس کمبود قابل اقدام انتخاب می‌شوند؛ confidence پایین به‌تنهایی مجوز سؤال نیست. گزارش روشن سؤال ندارد. جستجوی مبهم یک سؤال دکمه‌ای می‌گیرد؛ محتوای مبهم یک سؤال آزاد. بعد از دو سؤال، با جزئیات معلوم پیش‌نمایش ساخته می‌شود. دکمه «شفاف‌سازی بیشتر» فقط با انتخاب صریح شمار مجاز را یک مرحله افزایش می‌دهد؛ ثبت بدون آن همیشه ممکن است.

FAQ معتبر اول پاسخ می‌دهد و دو دکمه حل شد/هنوز مشکل دارم دارد؛ بله resolved بدون Issue؛ نه به گزارش همان گفتگو برمی‌گردد. بازگشتی /start کوتاه است و گفتگو نیمه‌تمام را پیشنهاد می‌کند. /my گزارش‌ها و مشارکت‌های مرتبط را نشان می‌دهد. کاربر فقط بات و کانال را می‌بیند؛ لینک مستقل گروه در منو نیست.

## ماتریس دکمه‌ها

callbackهای گفتگو قالب `i:ACTION:ID:REV[:ARG]` دارند؛ شناسه تصادفی کوتاه و طول کل زیر ۶۴ بایت است. منوهای فاقد اثر عمومی `menu:ACTION` هستند.

| متن | Action | حالت مجاز | عمل و حالت بعدی | تکرار/قدیمی | خطا و fallback |
|---|---|---|---|---|---|
| ثبت گزارش یا پیشنهاد | menu:new | همه جز publishing | شروع collecting | بی‌اثر پس از اولین رویداد | متن آزاد |
| پیگیری گزارش‌های من | menu:mine | همه | فهرست محلی مرتبط، بدون تغییر | خواندنی | /my |
| درباره مشارکت | menu:about | همه | توضیح حریم خصوصی | خواندنی | /privacy |
| ادامه گزارش | resume | collecting/clarifying/preview/help/editing | نمایش وضعیت فعلی | revision قدیمی رد و راهنمای ادامه | /continue |
| گزینه پاسخ | answer:INDEX | clarifying | ادغام متن گزینه، ارزیابی مجدد | فقط revision همان سؤال | متن آزاد |
| توضیح می‌دهم | free | clarifying | درخواست متن؛ همان سؤال دوباره شمرده نمی‌شود | قدیمی رد | متن آزاد |
| بدون جزئیات بیشتر | ready | clarifying/collecting | پیش‌نمایش اطلاعات موجود | idempotent | متن /done |
| ثبت گزارش | publish | preview | ساخت draft استاندارد و اجرای effect قبلی، published | تکرار شماره موجود؛ callback قدیمی هیچ انتشار ندارد | خطای API صف/reconcile |
| متن کامل گزارش | details | preview | نمایش متن کامل GitHub بدون انتشار | خواندنی؛ قدیمی رد | خلاصه و تأیید همچنان در دسترس |
| اصلاح | edit | preview | انتخاب عنوان/توضیح/سایر | قدیمی رد | ارسال اصلاح متنی |
| عنوان/توضیح/اطلاعات دیگر | title/body/other | preview | editing همان قسمت | یک بار تغییر revision | متن اصلاح‌شده |
| بازگشت | back | editing/preview | preview قبلی | قدیمی رد | /continue |
| افزودن تصویر | attach | preview/collecting | collecting، حفظ همه متن | قدیمی رد | پیام تصویری |
| حذف تصاویر | remove_media | preview/collecting | حذف پیوست‌های منتشرنشده | idempotent | ثبت متن بدون تصویر |
| توضیحاتم تموم شد | ready | collecting | استخراج و preview | idempotent | /done |
| انصراف | cancel | همه جز publishing/published | cancelled | بی‌اثر | /cancel |
| بله، همینه | duplicate:NUMBER | preview | subscribe و اتصال به Issue موجود، published | بدون Issue جدید | مشاهده لینک موجود |
| نه، متفاوته | different | preview | حذف مرحله مشابهت، همان preview | قدیمی رد | ثبت موضوع جدید |
| مشاهده گزارش | URL | preview/published | بازکردن پست کانال/Issue | خواندنی | لینک متنی |
| بله، ممنون | solved | help | resolved بدون Issue | بی‌اثر | متن «حل شد» |
| هنوز مشکل دارم | unresolved | help | مسیر گزارش با متن فعلی | بی‌اثر | توضیح آزاد |
| شفاف‌سازی بیشتر | more | preview | یک اجازه سؤال اضافی، clarifying | فقط با انتخاب صریح | ثبت بدون سؤال بیشتر |
| مشکل حل شده | fixed:NUMBER | اعلان بسته‌شدن | ثبت بازخورد؛ بدون تغییر وضعیت GitHub | idempotent | /feedback |
| هنوز مشکل دارم | persists:NUMBER | اعلان بسته‌شدن | پیش‌نویس توضیح برای همان Issue با رضایت | بدون reopen | /comment |

متن واقعی همه پیام‌های جدید در `src/messages/fa.json` قرار دارد؛ این کاتالوگ مرجع نهایی UX Writing است. خطای مدل به پیام فنی تبدیل نمی‌شود: قواعد و پیش‌نویس قابل ثبت باقی می‌مانند. خطای ارسال مبهم مانند قبل توقف و reconciliation دارد؛ به کاربر موفقیت ساختگی اعلام نمی‌شود.

## انتشار و حریم خصوصی

پیش‌نمایش متن کامل عمومی، تعداد تصویر و هشدار عمومی‌بودن را نشان می‌دهد. ایمیل، تلفن، کارت و توکن شناخته‌شده قبل از AI و انتشار حذف می‌شوند. نشانی و داده حساس ناشناخته ممکن است از فیلتر قطعی عبور کند؛ مدل هم تضمین تشخیص ندارد. کاربر باید متن و تصاویر را مرور کند. در نسخه فعال، حداکثر دو عکس آخر در یک درخواست مشترک مدل با کیفیت low بررسی می‌شوند؛ عکس به‌تنهایی مدرک بازتولید رفتار تعاملی نیست. محتوای تصاویر را قابل پالایش خودکار ادعا نمی‌کنیم. عکس فقط بعد از رضایت، از نشانی تصادفی عمومی قابل دریافت است؛ URL دانلود بله که توکن دارد هرگز عمومی نمی‌شود. /forget پیش‌نویس و ارتباط پیگیری خصوصی را حذف می‌کند؛ محتوای عمومی قبلی را خودکار پاک نمی‌کند.

## GitHub Governance

از Bug و Feature بومی موجود استفاده شود؛ نوع جدید بدون بررسی ساخته نشود. Content با `needs-content-review` و Documentation با label موجود documentation مشخص شوند. category labels قدیمی برای هشتگ و سازگاری پل حفظ می‌شوند؛ نیاز فنی آن‌ها نگاشت دسته کانال است. area labels فقط پس از آماده‌سازی واقعی مخزن ارسال شوند. اولویت اجرایی و Projects خودکار تغییر نمی‌کنند. اثر احتمالی صرفاً پیشنهاد triage است؛ هرگز اولویت قطعی مالک معرفی نمی‌شود.

قالب‌ها بخش‌های خالی را حذف می‌کنند و داده نامعلوم نمی‌سازند. Content شامل وضعیت «نیازمند بررسی متخصص» است؛ AI متن قرآن را اصلاح یا تأیید نمی‌کند. Issueهای مشابه ابتدا واژگانی بررسی می‌شوند؛ شباهت ضعیف مرحله اضافه نمی‌سازد. تأیید مشابهت فقط subscription می‌سازد؛ اطلاعات تازه فقط با تأیید جدا به کامنت تبدیل می‌شود.

دیدگاه‌های کم‌ارزش/تشکر/تأیید تکراری به GitHub کپی نمی‌شوند؛ مشارکت «من هم» به‌عنوان پیگیری ثبت می‌شود. متن مفیدِ پالایش‌شده و مرتبط به همان Issue منتقل می‌شود. بات به هر پیام پاسخ نمی‌دهد. تمام ادعاهای حل مشکل از GitHub استخراج می‌شوند؛ closed به‌تنهایی به معنی انتشار نسخه جدید نیست.

پیش‌نمایش عادی کوتاه و فارسی است. متن کامل فنی پشت دکمه «متن کامل گزارش» در دسترس است؛ برای هر گزارش چند پیام فنی اجباری ارسال نمی‌شود. اطلاعاتی که کاربر نوشته نیز با رضایت او بخشی از Issue خواهد بود.

## دکمه‌های افزوده و رفتار فعلی عکس

دکمه‌های کوتاه حداکثر دوتایی و گزینه‌های بلند تک‌ردیفی‌اند؛ متن نهایی از fa.json است. پیش‌نمایش اصلی ثبت، اصلاح، گزینه‌های بیشتر و انصراف دارد؛ در صورت وجود یک جزئیات مفید و بودجه سؤال، «تکمیل اختیاری» نیز نمایش داده می‌شود. کاربر هیچ‌وقت برای ثبت ملزم به ورود به این مسیر نیست.

| دکمه | action در قالب i:action:id:revision | state مجاز | عمل و state بعدی | تکرار/قدیمی | خطا و جایگزین |
|---|---|---|---|---|---|
| گزینه‌های بیشتر | options | preview | نمایش افزودن عکس/متن کامل/بازگشت؛ همان preview | مالک و revision کنترل می‌شوند | ارسال مستقیم عکس یا توضیح آزاد |
| تکمیل اختیاری | enrich | preview | یک سؤال مفید موجود در report؛ clarifying و افزایش شمار سؤال | بیش از سقف سؤال اجرا نمی‌شود؛ دکمه قدیمی رد | ثبت مستقیم از preview |
| پایان توضیحات | ready | collecting | تحلیل متن و حداکثر دو عکس آخر؛ سپس clarifying اگر ابهام اصلی هست، وگرنه preview | نتیجه AI به کلید رویداد cache می‌شود | AI ناموجود به قواعد و سؤال شرح تصویر برمی‌گردد |
| ادامه با همین‌ها | ready | clarifying | رد سؤال، preview با اطلاعات موجود و علامت needs-info در صورت لزوم | همان محافظ مالک/revision | پاسخ متنی، انصراف |

فرستادن عکس بدون کپشن مجاز است. چند عکس با انتخاب پایان توضیحات یک‌جا تحلیل می‌شوند؛ هر عکس جداگانه فراخوانی مدل نمی‌سازد. خطای دریافت عکس، توضیح همراهش را حذف نمی‌کند. عکس حداکثر چهار عدد و هرکدام ۱٫۵ مگابایت ذخیره می‌شود؛ برای تحلیل کم‌هزینه فقط دو مورد آخر فرستاده می‌شوند. نیازهای نامعلوم در Issue صریح می‌مانند و مشاهدات مدل برچسب نیازمند تأیید دارند.


### اصلاح خوانایی دکمه‌ها و امانت در خوانش تصویر — ۱۳ نوامبر
دکمه‌های کوتاه به ترتیب حداکثر دوتایی چیده می‌شوند؛ برچسب طولانی‌تر از ۱۲ نویسه (بدون ایموجی) یک ردیف کامل دارد. عرض نمایشگر از Bot API دریافت نمی‌شود، پس این قاعده محافظه‌کارانه است. عنوان‌ها کوتاه شده‌اند؛ callback و ترتیب عملیات حفظ می‌شود.
در نقل متن تصویر، املا، فاصله، اتصال حروف و شکل معیوب باید عیناً حفظ شود. خوانش نامطمئن باید نامطمئن اعلام شود؛ شکل صحیح یا مورد انتظار از متن مشاهده‌شده جداست. توضیح اصلاحی کاربر بر OCR مقدم است.
